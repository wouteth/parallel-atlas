This is a review of first-party product descriptions, repository documentation and a research paper, not an independent audit of their datasets or a hands-on test of every product. “AI-generated,” “built with AI” and “research agents” mean different things below.

## What to take from this

There are already history comparison apps and automated history projects. This search did not verify one product combining all our requirements: source-specific conflicting chronologies, deep time, undated narratives, passage-level citations, comparison links, maps and explicitly qualified cross-tradition connections. That is a bounded search finding, not a claim of uniqueness.

For the interface, keep track selection, shared dates and opening an event straightforward. Chrono Layers and Parallel are the most relevant product references from this search.

For later agent work, an offline workflow fits the current architecture: agents prepare proposed source records, include passages and dating rationale, run structural validation, then submit a reviewable repository diff. Reviewed files become the next static build. Visitors still only search and explore; no runtime agent service or database is required.

Source count should remain separate from evidence quality. Similarity matching should preserve disagreements and source dependence rather than combine accounts into a single asserted history. Automated schema checks can reject malformed records, but they cannot verify that a cited passage supports a claim.
